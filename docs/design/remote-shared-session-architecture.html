Pi (y)ours — Shared Session Architecture revised

One session, mirrored across surfaces, synchronized in real time. Share a new or existing chat; once a device is paired the “Connect” entry disappears and becomes a live sharing state.

1 · Core model

Single source of truth

The bound VS Code chat owns the transcript. The broker is a pure relay + registry. Every surface (VS Code, phone A, phone B…) renders from the same snapshot → they look and behave identically.

SharedSession (new object)

Binds chatResource ↔ brokerSessionId ↔ hostToken ↔ devices[] ↔ driverId ↔ connectionState. At most one per chat. Created when you Share; destroyed on Stop sharing.

Device (new)

A paired viewer: id (server‑minted), name (e.g. “iPhone · Safari”), role (spectator | driver), connectedAt. Sent to the host so VS Code can say shared with X.

Real‑time contract

Host change ⇒ snapshot fan‑out to all viewers. Presence change (join/leave/driver) ⇒ presence event to host + all viewers. Both sides re‑render from it — no surface can drift.

5 · Real‑time sync — event contract

host ──snapshot(transcript, working, model, connState)──▶ broker ──▶ every viewer viewer ──identify(deviceName)──▶ broker ──presence(devices[], driverId)──▶ host + viewers viewer ──claimDriver / releaseDriver──▶ broker ──driverChanged──▶ host + viewers viewer ──prompt(text)──▶ broker ──▶ host (applied to the bound chat only) host ──sessionEnded──▶ broker ──▶ viewers (show “ended”, nothing to reconnect to)
  • Presence is authoritative & immediate; snapshots are coalesced (~perf) but always full.
  • Both surfaces derive their info bar + status pill from the same presence + connState → guaranteed identical status.
  • Driver‑lock: one driver at a time; role changes broadcast so both sides agree instantly.

6 · Lifecycle & teardown

  • Start (new/existing) → reveal chat in initiating window → broker session → pairing panel.
  • Device joins → identify → presence → both show “shared with X / live”; Connect entry hidden.
  • Device leaves → presence(0) → state shared·idle (session alive, PIN re‑showable).
  • Stop sharing (info bar · status pill · panel) → broker session closed → viewers get sessionEnded → both revert (VS Code removes bar + restores Share; phone shows “ended”).
